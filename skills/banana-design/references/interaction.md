# Banana Design · 交互、状态与可访问性

## 一、Agent 界面的核心分层

编码与工具型 Agent 界面最稳定的一条规则：**执行细节留在消息流，决策动作放在输入框附近。**

```
┌─ 顶栏 56px ────────────────────────────────┐
│ 任务摘要（可折叠，展开限高 25vh）             │
├─ 消息区 flex-1（独立滚动）───────────────────┤
│  助手消息 / 工具调用卡 / diff / 终端输出       │
│  工具结果、diff、终端输出都留在这里             │
├─ 审批栏（工具类型不同，文案不同）────────────┤
├─ 输入区（吸底，随内容长高）──────────────────┤
└─────────────────────────────────────────────┘
```

具体规则：

- 审批按钮文案随工具类型变化：普通工具 `Approve / Reject`，写文件 `Save / Reject`，命令 `Run Command / Reject`，批量 `Approve / Deny`。
- 请求未完成时按钮禁用；响应后按"请求身份"加锁，防止重复提交。
- 工具预览可折叠放在消息流，操作按钮固定在输入区上方，两者不混在一起。
- diff 有两套：聊天内单列增删可折叠；IDE 里走编辑器的 diff 视图。

## 二、输入框

必做的四件事：

1. **自动增高**，到上限后内部滚动。
   - `min-height` 40px（单行），上限 192px（普通）/ 400px（长任务）
   - 换行行数上限 3–10 行，随产品定
2. **Enter 发送 / Shift+Enter 换行**，并且做中文输入法保护：
   ```ts
   if (e.nativeEvent.isComposing || e.keyCode === 229) return;
   ```
3. **"Enter 何时算发送"按产品定死。** 参考两种常见做法：
   - 有文字一律发送，空框才当停止（连续打断场景友好）
   - 移动端 Enter 换行，靠按钮发送
4. **发送语义可选**：`enter` / `ctrlEnter` / `none`，另可加 Cmd/Ctrl+Shift+Enter 的 steer（不打断当前生成，追加指令）。

其它：

- 提交按钮在无内容时禁用。
- 输入框在流式输出时保持可编辑，不要锁死。

## 三、滚动

- 消息区独立滚动，输入区固定，不随内容滚走。
- 贴底跟随用 `requestAnimationFrame`。
- 必须区分"用户主动上滚"和"内容变短"：用户上翻后停止跟随，并显示"回到底部"按钮。
- 只读"是否在底部"，不要用"接近底部"，否则虚拟滚动会抢滚动权。
- 加载时绝不改变滚动位置。
- 滚动条宽度 6px，自定义样式不影响滚动容器本身。

## 四、流式输出

### 渲染

- Markdown 按块增量解析：记住稳定块边界，每帧只重解析尾部，变化块用 `memo` 包住。
- 代码高亮在流式过程中跳过分词，等块稳定后再高亮。
- 折叠的思考过程、工具参数用 `useDeferredValue` 降优先级。

### 反馈

- 流式光标：11px 圆点呼吸动画，或等宽的 `▍`。
- 等待态用扫光渐变，不用打字机。扫光让一行内多个片段共用一道波。
- 三点跳动用错开延时（-0.32s / -0.16s / 0s）。

### 状态管理

- 流式消息的元数据里标乐观标记，乐观消息不落库。
- 发送队列串行化，避免快速连发打乱顺序。
- 失败时把乐观清空的输入内容回填。

## 五、动效

| 场景 | 时长 |
| --- | --- |
| 状态变化、悬停、聚焦 | 100–200ms |
| 浮层（菜单、popover） | 150–300ms |
| 弹窗 | ≤ 300ms |
| 抽屉 | 弹簧：开 1.0 @ 0.38s，释放 0.86 @ 0.32s，关 1.0 @ 0.28s |

- 缓动统一 `--ease-out`；进场可以用 `cubic-bezier(0.16, 1, 0.3, 1)`，退场稍慢。
- 优先动 transform 与 opacity；允许颜色过渡；不动会触发布局的属性。
- 按下缩放到 0.985。
- 浮层进场从 0.95 缩放并配合 clip-path 展开。
- 复制成功就地变对勾，2 秒后复原，通过 live region 播报，不用 toast。
- 循环动画在离屏、后台标签页、减弱动效偏好时暂停。

## 六、可访问性清单

- [ ] 正文对比 ≥ 4.5:1，控件与图标 ≥ 3:1，明暗两套都验
- [ ] 每个可交互元素有可见 `:focus-visible` 焦点环，禁止 `outline: none`
- [ ] 焦点环与接触的底色 ≥ 3:1
- [ ] 触屏点击区 ≥ 44px
- [ ] 状态不只靠颜色，配图标或文字
- [ ] 装饰性 SVG 标 `aria-hidden`，纯图标控件给可访问名
- [ ] 弹窗困住焦点，关闭归还焦点
- [ ] 单键快捷键能跳过文本框，带修饰键的组合不冲突
- [ ] 布局用逻辑属性，支持 RTL
- [ ] 关键信息不只靠 hover
- [ ] 动效支持 `prefers-reduced-motion`
- [ ] 目标 WCAG 2.1 AA

## 七、文案规范

- 术语表固定，同一概念不用不同同义词。
- 同一动作全站同一个动词；动作名用"动词 + 名词"（`保存草稿`，不是 `确定`）。
- 进行中用现在分词加省略号：`生成中…`、`保存中…`。
- 确认结果说清具体变了什么，跳过"成功"和最高级形容。
- 敏感消息按三步排序：承认情况 → 恢复控制 → 给出下一步。
- 信息与温度默认 8:2，关键时刻最多 7:3。
- 界面文案里不用冒号（代码、命令、URL、时间、数据标签除外）。
- 写陈述句，不用反问句。
- 不说教式鼓励，不宏大叙事，不过度拟人化。用户拥有判断权和最终决定权。
- 空位就留空，不为配版面写一句话。
- 辅助文案说明结果，不重复选项。
- 用户可见文案走 i18n，键名用 `CATEGORY$IDENTIFIER` 约定。
